### 模块8 维护与排障（从日常巡检备份到六大Windows诊断工具，建立"预防—定位—恢复"的运维闭环）
#### 任务31 日常维护
##### 8.1 例行检查与维护【页码待核：在线无公开页码】
- 核心概念：网络日常例行检查指按固定周期对设备状态进行巡检，主要包括CPU与内存使用率、风扇与电源工作状态、端口流量与错包/丢包、日志信息、配置与固件一致性等。目的是在故障发生前发现隐患、留痕可追溯。中职阶段强调建立"日检、周检、月检"巡检表，逐项记录并签字，形成运维台账。
- 关键命令/配置步骤：纯概念小节，无命令（演示用查看命令）。巡检时常用查看命令：
```text
display cpu-usage            # CPU利用率
display memory-usage         # 内存利用率
display interface GigabitEthernet0/0/1   # 端口流量与错包
display logbuffer            # 日志缓冲区
display device                # 风扇、电源、板卡状态
```
- 教学要点：生活类比——例行检查像车的定期保养，换机油、查胎压，别等抛锚在路上才修。板书要点：巡检五类对象（CPU/内存、硬件、端口、日志、配置）+周期表。课堂演示：在eNSP路由器上敲`display cpu-usage`与`display logbuffer`，教学生读懂输出字段。
- 答辩角度：
  一、问：巡检发现端口错包增长快说明什么？答：可能网线质量差、双工不匹配或接口故障，需换线/查协商。
  二、问：为什么要留巡检记录？答：便于趋势对比、故障回溯与责任界定。
  前后关联：开启模块8运维话题，与8.2配置备份构成"看状态—留后路"两件套。
##### 8.2 定期备份配置文件【页码待核：在线无公开页码】
- 核心概念：设备配置文件是网络的"灵魂"。定期备份即把当前生效配置保存、归档到flash或通过TFTP/SCP上传到运维主机，以便设备故障或误操作后快速恢复。关键命令包括`save`保存当前配置、`display startup`查看下次启动加载文件、`display saved-configuration`查看已保存配置。
- 关键命令/配置步骤：
```text
display saved-configuration        # 查看已保存的配置
save                               # 将当前配置写入启动配置文件
display startup                    # 查看本次/下次启动加载的文件
### 备份到flash
copy flash:/vrpcfg.zip flash:/bak_20261027.zip
### 再通过TFTP上传到运维主机归档（在设备侧执行）
tftp 192.168.1.100 put vrpcfg.zip
```
- 教学要点：生活类比——备份像给重要文件做云同步+U盘双份，设备崩了也能一键还原。板书要点：三命令（save、display startup、copy）+两个去向（本地flash、TFTP主机）。课堂演示：先`display startup`看启动文件，`save`后`display saved-configuration`核对，再copy一份备份文件。
- 答辩角度：
  一、问：current-configuration与saved-configuration区别？答：前者是当前内存中的运行配置，后者是已保存到flash的启动配置；`save`才把前者写盘。
  二、问：只copy到本地flash够吗？答：不够，设备整机损坏时flash也丢失，必须再上传到外部主机归档。
  前后关联：承接8.1巡检，强调"预防"；与任务32故障排除形成"先备份再排障"的安全操作习惯。
#### 任务32 网络故障排除
##### 8.3 ipconfig【页码待核：在线无公开页码】
- 核心概念：ipconfig是Windows查看本机网络配置的命令。`ipconfig`仅显示基本IP/掩码/网关；`ipconfig /all`显示完整信息，含网卡物理地址（MAC）、DHCP与DNS服务器、租约时间等。它是排障第一步——先确认"本机到底拿到了什么地址"，再怀疑网络。
- 关键命令/配置步骤：
```text
ipconfig                         # 简要IP配置
ipconfig /all                    # 完整配置（含MAC、DNS、DHCP、租约）
ipconfig /release                # 释放DHCP地址
ipconfig /renew                  # 重新向DHCP申请地址
ipconfig /flushdns               # 清除DNS解析缓存
```
- 教学要点：生活类比——ipconfig像查自己的身份证，先确认"我是谁、住哪个门牌号"，再去怪邻居路不通。板书要点：/all看四件事（IP、掩码、网关、DNS）+release/renew重置DHCP。课堂演示：在Windows虚拟机跑`ipconfig /all`，指出IPv4地址、默认网关、物理地址三行。
- 答辩角度：
  一、问：ipconfig /all看到169.254.x.x说明什么？答：未从DHCP拿到地址，Windows自动私有地址，应查DHCP或网线。
  二、问：flushdns解决什么问题？答：改了DNS或网站IP后本机仍解析到旧地址时，清缓存。
  前后关联：排障工具链第一环，后续ping验证连通性。
##### 8.4 ping【页码待核：在线无公开页码】
- 核心概念：ping基于ICMP回显请求/应答，测试本机到目标IP是否可达及时延、丢包情况。它是排障最常用工具：先ping本机网关（查内网连通），再ping外网IP（查路由），最后ping域名（查DNS）。`-t`持续ping、`-n`指定次数、`-l`指定包大小。
- 关键命令/配置步骤：
```text
ping 192.168.1.1                 # ping网关
ping -t 192.168.1.1              # 持续ping，Ctrl+C停止
ping -n 10 8.8.8.8               # 发10个包
ping -l 1000 www.baidu.com       # 每个包1000字节，测大包连通
```
- 教学要点：生活类比——ping像给对方打电话"喂？听得见吗？"，能通说明线好，超时说明没人接或线断了。板书要点：排障顺序（先网关后外网再域名）+三种典型结果（通、请求超时、无法访问目标主机）。课堂演示：先ping通网关，再把网线拔掉观察"请求超时"。
- 答辩角度：
  一、问：ping域名失败但ping IP成功说明什么？答：网络通但DNS解析有问题，查DNS配置或flushdns。
  二、问：ping通但网页打不开可能？答：ICMP通但应用层问题，如DNS、代理、浏览器或服务端口。
  前后关联：承接8.3本机地址，进入连通性测试；与8.6 tracert配合——ping通不了时用tracert定位断点。
##### 8.5 arp【页码待核：在线无公开页码】
- 核心概念：ARP（地址解析协议）将IPv4地址解析为MAC地址，Windows用ARP缓存表记录映射。`arp -a`查看缓存；`arp -d`清空缓存；`arp -s`手工绑定静态条目。排障中用于发现IP冲突、验证网关MAC、识别ARP欺骗（网关MAC异常）。
- 关键命令/配置步骤：
```text
arp -a                           # 查看ARP缓存表
arp -d                           # 清空ARP缓存
arp -s 192.168.1.1 00-01-02-aa-bb-cc   # 静态绑定网关IP与MAC
```
- 教学要点：生活类比——ARP像通讯录，把"人名（IP）"对应到"手机号（MAC）"；通讯录错了，电话就打错人。板书要点：作用（IP→MAC）+三条命令（-a查、-d清、-s绑）。课堂演示：先`ping网关`再`arp -a`，看到网关IP对应的MAC条目。
- 答辩角度：
  一、问：如何识别ARP欺骗？答：arp -a中网关IP对应到了非真实网关MAC，或MAC频繁变化。
  二、问：arp -s静态绑定防什么？答：防ARP欺骗篡改网关映射，固化网关MAC。
  前后关联：承接ping（三层连通），下沉到二层地址解析；与7.4端口安全的MAC表概念呼应。
##### 8.6 tracert【页码待核：在线无公开页码】
- 核心概念：tracert（路由跟踪）通过递增TTL的ICMP报文，列出从本机到目标路径上经过的每一跳路由器地址，定位"在哪一跳断了"。`-d`不解析主机名以加速。当ping不通时，tracert能告诉你是第一跳（内网）就断，还是后面某一跳断。
- 关键命令/配置步骤：
```text
tracert www.baidu.com            # 跟踪到目标的路径
tracert -d 202.103.0.1           # -d 不做域名解析，更快
```
- 教学要点：生活类比——tracert像快递查物流，一件包裹卡在哪个中转站一目了然。板书要点：原理（TTL递增）+用法（-d加速）+用途（定位断点跳）。课堂演示：tracert到外网域名，观察前几跳是网关、后几跳是运营商路由器。
- 答辩角度：
  一、问：tracert显示第一跳就超时说明？答：内网/网关侧问题，查本机IP、网线、交换机端口。
  二、问：tracert与ping区别？答：ping只测端到端通否，tracert列出路径每一跳，定位断点。
  前后关联：承接8.4 ping，用于"ping不通时精确定位"；与8.7 route print配合判断路由错误。
##### 8.7 route print【页码待核：在线无公开页码】
- 核心概念：route print查看Windows本机路由表，列出目的网络、掩码、网关、接口与跃点。排障中用于确认本机默认网关与静态路由是否正确。`route add`手工添加静态路由，`route delete`删除。本机路由错误会导致"能ping网关却上不了外网"。
- 关键命令/配置步骤：
```text
route print                     # 查看完整路由表
route print -4                  # 只看IPv4
route add 192.168.100.0 mask 255.255.255.0 192.168.1.1   # 加静态路由
route delete 192.168.100.0      # 删除静态路由
```
- 教学要点：生活类比——路由表像导航地图，告诉电脑"去哪个方向该走哪条路"；地图错了就绕远或迷路。板书要点：看两行（默认路由0.0.0.0、对应网关）+add/delete。课堂演示：`route print`找到`0.0.0.0`默认路由那一行，指出它就是"上外网的出口"。
- 答辩角度：
  一、问：route print中0.0.0.0路由含义？答：默认路由，所有未知目的网段都交给它指定的网关转发。
  二、问：能ping通网关却上不了外网先查什么？答：查本机默认路由（route print）与DNS，再查出口NAT/防火墙。
  前后关联：承接tracert定位断点，结合route print判断是否本机路由错误；与9.1三层局域网静态路由知识点呼应。
##### 8.8 netstat【页码待核：在线无公开页码】
- 核心概念：netstat查看本机网络连接、端口监听、路由表与统计信息。常用`netstat -ano`：-n不解析名字（数字显示）、-o显示占用连接的进程PID、-a显示所有连接与监听端口。用于排查"哪个程序占用了端口""本机与谁建立了连接"。
- 关键命令/配置步骤：
```text
netstat -ano                    # 所有连接+数字+PID
netstat -ano | findstr :80      # 筛选80端口相关连接
netstat -r                      # 等同route print，显示路由表
netstat -b                      # 显示每个连接对应的程序名（管理员）
```
- 教学要点：生活类比——netstat像查"家里谁在跟谁打电话、占了哪条电话线"，发现不明连接就能揪出可疑程序。板书要点：三个参数（-a全部、-n数字、-o PID）+findstr过滤端口。课堂演示：`netstat -ano | findstr :445`观察，再用任务管理器按PID找到对应进程。
- 答辩角度：
  一、问：netstat -ano中LISTENING与ESTABLISHED区别？答：LISTENING是端口在等待接入，ESTABLISHED是已建立的活跃连接。
  二、问：如何根据PID找进程？答：任务管理器→详细信息→按PID列，或`tasklist | findstr <PID>`。
  前后关联：排障工具链收口——从地址、连通、二层、路径、路由到连接进程，定位到具体程序。
##### 8.9 任务总结【页码待核：在线无公开页码】
- 核心概念：网络故障排除遵循"先物理后逻辑、先链路后网络、先本机后网络、分段排查"的思路，对照OSI七层逐层定位。物理层查网线/端口灯，数据链路层查VLAN/MAC/端口安全，网络层查IP/路由/ACL，应用层查DNS/服务。工具链固定顺序：ipconfig查本机→ping测连通→arp查映射→tracert定位断点→route print查路由→netstat查端口与进程。
- 关键命令/配置步骤：纯总结小节，无命令。流程要点：①记录故障现象与范围；②从本机出发逐跳测试；③分层缩小范围；④定位后修复并回归验证；⑤记录归档。
- 教学要点：生活类比——排障像医生问诊，先量体温（本机）、再拍片（连通）、最后对症下药，不瞎猜。板书要点：分层排障树（物理→链路→网络→应用）+工具顺序六连。课堂演示：给定一个"全网不通"场景，让学生按顺序说出先敲哪条命令。
- 答辩角度：
  一、问：整机排障标准顺序？答：先ipconfig看本机→ping网关→ping外网IP→ping域名→arp/route/netstat逐层定位。
  二、问：为什么先本机后网络？答：80%故障出在本机配置（IP、网关、DNS），先排除本机再查网络节省时间。
  前后关联：收口任务32，串联8.3—8.8六个工具；为模块9综合实训中"边部署边排障"提供方法论。
